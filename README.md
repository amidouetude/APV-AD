APV_AD_Project
===============

Overview
--------
This repository implements models and notebooks for evaluating integrated agrivoltaic (APV) + anaerobic digestion (AD) systems and optimizing design variables using a combined eLER objective (crop yield, PV production, and biogas). The pipeline is organized as a sequence of notebooks that: prepare data, define physical models, run optimizations, post-process results and produce figures used in the manuscript.

Key features
- Modular physical models (solar geometry, shading, POA, bifacial PV, crop PAR model, ET savings, anaerobic digestion energy balance).
- Models are implemented interactively in notebooks and exported as an importable script (`simulation_functions.py`) for optimization.
- A pytest test suite (`tests/`) covers all core functions, parametrized across all four study sites, plus a real-data end-to-end smoke test — see **Testing** below.
- CI runs the test suite and a notebook/export consistency check on every push and pull request — see **Continuous Integration** below.
- An associated LaTeX manuscript in `paper/` documents methods and results, including a Pareto trade-off supplementary figure (`notebooks/07_pareto_analysis.py`) and a model-limitations summary table.
- Supplementary validation and sensitivity analyses referenced by the manuscript are in `docs/` — see **Validation & sensitivity artifacts** below.

Quick start (recommended)
-------------------------
1. Create a Python virtual environment (recommended: venv or conda). Example using venv:

   Windows (PowerShell):
   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

   Or using conda:
   ```bash
   conda create -n apvad python=3.10
   conda activate apvad
   pip install -r requirements.txt
   ```

2. Open the notebooks in your preferred Jupyter environment (JupyterLab, classic notebook, or VS Code).

3. Run the notebooks in order:
   - `01_load_data.ipynb`  — prepare hourly climate CSVs used by the pipeline.
   - `02_simulation.ipynb` — defines physical models, runs unit tests, and exports `simulation_functions.py`
   - `03_optimizer.ipynb`  — runs Differential Evolution optimization and local polishing using exported functions
   - `04_metrics.ipynb`    — postprocesses optimized results and writes `outputs/csv/results_summary.csv`
   - `05_figures.ipynb`    — produce plots for the manuscript
   - `06_validation.ipynb` — validation checks conducted in the analysis
   - `07_pareto_analysis.py` — optional: bi-objective (eLER vs. water savings) NSGA-II search producing the manuscript's Pareto-front supplementary figure; see **Pareto trade-off analysis** below

Important: run `02_simulation.ipynb` before `03_optimizer.ipynb` because 02 exports `simulation_functions.py`. The exported file has a header: "Auto-generated by 02_simulation.ipynb — DO NOT EDIT MANUALLY"; to change model code, edit the notebook and re-run the export cell. CI enforces this automatically — see below.

Files & structure
-----------------
- `notebooks/`
  - `config_00.py`        : central configuration (SITES, PARAMS, DE_SETTINGS, SCENARIOS). Also the single source of truth for physical/geometry constants (module dimensions, field layout) — `simulation_functions.py` reads these from `PARAMS` rather than hardcoding them, so a change here propagates everywhere on the next export.
  - `01_load_data.ipynb`   : ingest and prepare hourly climate data (writes `hourly_{site}.csv` in `outputs/csv/`)
  - `02_simulation.ipynb` : defines physics models & unit tests; exports `simulation_functions.py`
  - `03_optimizer.ipynb`  : optimization workflow (scipy.optimize Differential Evolution + polishing)
  - `04_metrics.ipynb`    : postprocessing, economic calculations, writes `outputs/csv/results_summary.csv`
  - `05_figures.ipynb`    : figures for manuscript
  - `06_validation.ipynb` : validation checks and sensitivity analyses
  - `07_pareto_analysis.py` : standalone script (not a notebook) — bi-objective NSGA-II search, see **Pareto trade-off analysis** below
- `tests/`               : pytest suite — see **Testing**
- `data/`                : input climate files used by the notebooks (`hourly_{site}.csv`); `data/ci_sample/` holds a small real-data fixture for CI (see below)
- `docs/`                : validation and sensitivity analysis write-ups referenced by the manuscript (see below)
- `outputs/`              : generated results and figures (created by the notebooks)
- `paper/`                : LaTeX manuscript and sections
- `.github/workflows/tests.yml` : CI configuration

Testing
-------
`tests/test_simulation_functions.py` covers `compute_solar_angles`, `compute_shading`, `compute_POA`, `compute_PV`, `compute_crop_yield`, `compute_ET_reduction`, `compute_AD`, `eLER_weighted`, and `eLER_objective` using small synthetic hourly fixtures (fast, no external data required). Site-dependent tests are parametrized across all four study sites (Konya, Almería, Ouagadougou, Freiburg) via a `site` pytest fixture, not just one representative site — this matters in practice, since each site has different feasibility bounds (e.g. `min_beta_deg`, fruit yield) that a single-site test can miss.

`tests/test_notebook_smoke.py` runs the full six-model pipeline end-to-end against a genuine slice of real PVGIS data (`data/ci_sample/hourly_Konya_sample.csv`, ~60 KB, see `data/ci_sample/README.md` for provenance) rather than only synthetic inputs.

Run the full suite:
```bash
pip install pytest
pytest tests/ -v
```

Continuous Integration
-----------------------
`.github/workflows/tests.yml` runs on every push and pull request, with two jobs:
- `pytest` — the full test suite above (synthetic + real-data smoke test).
- `notebook-export-drift-check` — regenerates `simulation_functions.py` from `02_simulation.ipynb`'s function-definition and export cells (no climate data or live kernel required) and diffs it against the checked-in file. This catches the most common real-world failure mode: someone edits a function in the notebook and forgets to re-run the export cell, silently desynchronizing the notebook (the source of truth) from the `.py` file everything else imports.

Validation & sensitivity artifacts
-----------------------------------
`docs/` contains the detailed derivations and quantified before/after impact for each model correction referenced in the manuscript and in code comments:
- `docs/poa_azimuth_fix_notes.md` — angle-of-incidence and solar-time (longitude/equation-of-time) corrections, including the pvlib cross-check that surfaced the longitude bug.
- `docs/pvlib_validation.md` — external validation of the POA irradiance model against `pvlib`'s isotropic and Perez transposition models.
- `docs/et0_ra_fix_notes.md` — the two ET0/Hargreaves-Samani corrections (extraterrestrial radiation estimation, and the MJ-to-mm conversion factor).
- `docs/ad_bmp_sensitivity.md` — Monte Carlo sensitivity analysis of AD/BMP parameters (`BMP_ref`, capture efficiency, VS fractions).
- `docs/eLER_weighting_sensitivity.md` — justification and sensitivity analysis for eLER's equal component weighting, including comparison against economic- and energy-content-weighted alternatives.

Each file documents: what was wrong, how it was found, the fix, quantified impact, reproducible code, and links to the specific regression test(s) guarding against recurrence.

Pareto trade-off analysis
--------------------------
`notebooks/07_pareto_analysis.py` runs the bi-objective NSGA-II search (maximise eLER and `LER_water` jointly) specified in the manuscript's Methodology (Section 3.9.3) but not wired up as a runnable script until this addition. It reproduces `paper/figures/fig10_pareto_eler_water.png`, the Pareto-front figure in the Discussion ("Beyond the scalar optimum: a Pareto perspective").

Requires `pymoo` (`pip install pymoo`; add to `requirements.txt` if not already present). Run after `01_load_data.ipynb` (needs `outputs/csv/hourly_{site}.csv`) and after `02_simulation.ipynb` has been run at least once (needs `notebooks/simulation_functions.py` to exist):

```bash
cd notebooks
python 07_pareto_analysis.py --site Konya --pop 50 --gen 80 --scalar-eler-optimum 1.641
```

`--scalar-eler-optimum` should be the site's own eLER value from Table 9 (Konya=1.641 is the manuscript's default); pass the corresponding value if running a different site. Output is written to `outputs/figures/fig10_pareto_eler_water.png`. Full default settings (50×80=4,000 evaluations) take roughly the same runtime as one site's DE run in `03_optimizer.ipynb`.

Data expectations
-----------------
- The loader expects files named `hourly_{site}.csv` in the directory referenced by `CSV_DIR` in `config_00.py`.
- Expected columns used by the pipeline include (at least): `GHI`, `DNI`, `DHI`, `T2m`, `WS`, `in_season`.
- `data/ci_sample/` holds a small (720-hour, ~60 KB) real-data fixture for fast CI checks — see `data/ci_sample/README.md`.

Model corrections since the original submission
--------------------------------------------------
In response to peer review, six corrections were made to `simulation_functions.py` (all backward-compatible where the function is still called with its original arguments, except where noted):

1. **Angle of incidence** (`compute_POA`) — replaced a solar-noon-only approximation with the exact Duffie & Beckman closed-form expression for a fixed, due-south collector. *Breaking change: `compute_POA` now requires `lat_deg`.*
2. **eLER component weighting** (`eLER_weighted`, new function) — made the previously-implicit equal weighting explicit and adjustable, with a sensitivity analysis against economic and energy-content alternatives. Fully backward-compatible (`eLER_objective`'s default weights reproduce the original unweighted sum exactly).
3. **ET0 / Hargreaves-Samani** (`compute_ET_reduction`) — two fixes: (a) extraterrestrial radiation now computed astronomically (FAO-56) instead of from a fixed GHI clearness-index proxy; (b) added a previously-missing MJ-to-mm conversion factor. No signature change.
4. **AD parameter sensitivity** (`compute_AD`, `eLER_objective`) — added an optional `AD_overrides` dict enabling Monte Carlo sensitivity analysis on `BMP_ref`, capture efficiency, and VS fractions without mutating global config. Fully backward-compatible (`AD_overrides=None` reproduces prior behavior exactly).
5. **Solar time / longitude correction** (`compute_solar_angles`) — hour angle now accounts for site longitude and the equation of time; previously assumed solar noon at 12:00 UTC everywhere. *Breaking change: `compute_solar_angles` now requires `lon_deg`.* Found via the `pvlib` cross-check in item 1 above.
6. **Centralized geometry constants** — `MODULE_LENGTH_M`, `MODULE_WIDTH_M`, `ROW_LENGTH_M`, `LAND_AREA_M2` were previously hardcoded as literals in three separate places; now sourced from `config_00.PARAMS` as a single source of truth.

See `docs/` above for full derivations and quantified impact of items 1, 2, 3, and 4. All fixes are covered by regression tests in `tests/test_simulation_functions.py`.

Optional: higher-fidelity options
---------------------------------
- The POA irradiance model has been validated against `pvlib`'s isotropic and Perez transposition models (see `docs/pvlib_validation.md`); the residual gap versus Perez (1.5–3.9%) reflects the isotropic-vs-anisotropic sky-diffuse modeling choice and is documented as a stated limitation rather than a further fix.
- Replace the ET0 proxy with full Penman–Monteith when RH/wind-speed data are available for improved crop-water estimation accuracy (Hargreaves-Samani agrees with FAO-56 Penman-Monteith to within ±10% for the climates studied here — see manuscript Section 3.6 and `docs/et0_ra_fix_notes.md`).

Troubleshooting
---------------
- If a notebook raises `FileNotFoundError` about `hourly_{site}.csv`: run `01_load_data.ipynb` first and ensure `CSV_DIR` in `config_00.py` points to the correct folder.
- If `simulation_functions.py` is out-of-sync with the notebook, re-run the export cell in `02_simulation.ipynb` (the notebook prints the path where `simulation_functions.py` is saved). CI's `notebook-export-drift-check` job will fail on a pull request if this happens and wasn't caught locally.
- If package import errors occur, create a fresh virtual environment and install `requirements.txt` as shown above.

Contributing
------------
Suggested workflow:
1. Clone or copy the repository into a workspace.
2. Create a feature branch for changes to notebooks or config.
3. Edit notebooks (preferably the canonical versions), re-run tests and the export cell in `02_simulation.ipynb` to regenerate `simulation_functions.py`.
4. Add or update unit tests in `tests/` for any new/changed model logic — parametrize across all four sites if the change is site-dependent (see **Testing** above for why).
5. Run `pytest tests/ -v` locally before opening a PR; CI will also run it automatically.
6. Open a PR with a clear description and include `outputs/csv/results_summary.csv` for verification when appropriate.
